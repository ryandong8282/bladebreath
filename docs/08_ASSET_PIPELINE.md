# Unity 资产生产流程

## 原则

AI 可以帮助概念探索、贴图草案、图标草案和低模起点，但“生成了一张好看图片”不等于“已经有可用游戏资产”。进入 Unity 的生产资源必须具备稳定比例、干净拓扑、UV、材质、绑定、动作、真机预算和明确授权。

历史题材多一条：**好看不等于属于这个时代。** 每项正式资产必须说明历史锚点与架空改动。

## 从研究到游戏的最短链路

```text
玩法需求
→ 历史锚点卡
→ 轮廓草图 / 情绪板
→ 正侧背设定
→ Blender 低模 Blockout
→ 拓扑与 UV
→ 风格化材质
→ 骨骼与动作
→ FBX / 贴图导入 Unity
→ Prefab、碰撞与命中点
→ 手机可读性测试
→ 性能与授权登记
```

历史锚点卡至少记录时代、地区、身份、材料、参考来源和明确不能出现的后世元素。

## 当前 M0.3

Unity 灰盒只使用原生 Capsule、Cube、Plane 和代码材质，用来验证：

- 人物与武器尺寸；
- 攻击距离和碰撞；
- 镜头俯角；
- 场地空间感；
- HUD 是否遮挡交锋；
- 预警色是否能在手机尺寸下区分；
- 架势崩溃和处决是否看得懂。

M0 不评价角色是否“帅”，只评价信息是否可读、气质是否跑偏。

## M1 概念资源

允许探索：

- 无铭者与执刃者黑白剪影；
- 北齐石灰岩、残彩、鎏金、灰窑、旧铜材质板；
- 弹反、拼刀、崩势和陶釉裂纹 VFX 关键帧；
- HUD 与技能图标草案；
- 校刀院俯视构图；
- 镇军长刀正侧面设计。

每次只解决一个视觉问题，不批量制造几十张互相不一致的“古风美图”。

## 3D 生产职责

生成工具可以给形体起点，但生产链仍包含：

1. 轮廓确认；
2. 多视图一致性校正；
3. 可动画拓扑；
4. UV 与材质合并；
5. 骨骼和权重；
6. 攻击关键姿势；
7. Unity Prefab、Collider 与 Hitbox；
8. Animator / Animation Clip 设置；
9. iPhone 实机性能；
10. 来源和许可登记。

任何一步不合格，都不能因为“截图挺牛逼”跳过。

## M3 正式低模预算（首版建议）

| 资产 | 三角面目标 | 材质槽 | 骨骼 |
|---|---:|---:|---:|
| 无铭者 | 18k–30k | 2–3 | 55–75 |
| 造像署执刃者 | 10k–20k | 1–2 | 45–65 |
| 校刀令·迟盖 | 25k–40k | 2–3 | 60–85 |
| 长刀 | 1k–4k | 1 | 0–2 |
| 小场景模块 | 0.5k–8k | 1 | 0 |

预算是上限起点，不是必须用满。轮廓、动作、批次和纹理内存优先于小配件。

## Unity 导入约定

- 1 Unity Unit = 1 米；
- Y 轴向上，角色面向本地 `+Z`；
- 角色根节点在脚底中心；
- 生产交换格式优先 `.fbx`；源文件可保留 `.blend`，但不要依赖 Unity 直接读取某台电脑上的 Blender 安装；
- 动画 Clip 使用英文 `snake_case`；
- 骨骼、网格、材质和动画命名稳定，不用 `final_final_2`；
- 材质先使用 URP/Lit 或项目批准的 Shader Graph；
- 贴图尺寸、压缩、MipMap、色彩空间和平台 Override 必须检查；
- 频繁复用对象做 Prefab，不把同一模型手工复制成多个分叉版本；
- Unity 生成的 `.meta` 必须跟资产一起提交；
- 大型二进制资产进入前先决定 Git LFS，而不是提交后再补救；
- 每个外部或生成资产登记来源、作者、工具、日期、许可和修改记录；
- 文物参考图未经授权与处理，不得直接投射成游戏贴图。

## 验收问题

正式资产只有全部回答“是”才可替换灰盒：

1. 缩到手机实际显示尺寸后仍能辨认朝向吗？
2. 前摇关键姿势不靠红圈也看得懂吗？
3. 武器视觉长度与命中范围相符吗？
4. 换模型后保持原战斗时间点吗？
5. 目标设备满足帧率、内存和纹理预算吗？
6. 授权链条能公开说明吗？
7. 历史锚点与架空改动写清楚了吗？
8. 是否排除了明显后世或异文化模板？
