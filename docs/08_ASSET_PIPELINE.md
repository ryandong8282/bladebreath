# 资产生产流程

## 原则

AI 可以帮助概念探索、贴图草案、图标草案和低模起点，但不能把“生成了一张好看图片”误认为“已经有可用游戏资产”。进入游戏的 3D 资源必须具备稳定比例、干净拓扑、UV、材质、绑定、动作、真机预算和明确授权。

历史题材还多一条：**好看不等于属于这个时代。** 每项正式资产必须能说明历史锚点与架空改动。

## 从研究到游戏的最短链路

```text
玩法需求
→ 历史锚点卡
→ 轮廓草图 / 情绪板
→ 正侧背设定
→ 低模 Blockout
→ 拓扑与 UV
→ 风格化材质
→ 骨骼与动作
→ Godot 导入
→ 手机可读性测试
→ 性能与授权登记
```

历史锚点卡最少记录：时代、地区、身份、材料、参考来源、明确不能出现的后世元素。

## M0.2

使用程序化几何体和 Canvas 图形。它们验证：

- 人物与武器尺寸；
- 攻击距离；
- 镜头俯角；
- 地面空间感；
- UI 是否遮挡战斗；
- 石灰白玩家与烟黑敌人的轮廓分工；
- 灰窑铜火、军令碑和巨像剪影是否足以建立第一层世界感。

M0 不评价角色是否“帅”，只评价信息是否看懂、气质是否跑偏。

## M1 概念资源

允许生成：

- 无铭者与执刃者黑白剪影；
- 北齐石灰岩、残彩、鎏金、灰窑、旧铜的材质情绪板；
- 弹反、拼刀、崩势和陶釉裂纹的 VFX 关键帧；
- HUD 与技能图标草案；
- 校刀院灰窑外院俯视构图；
- 镇军长刀的正侧面武器设计。

每次只解决一个视觉问题，不批量生成几十张互相不一致的“古风美图”。

## 3D 资产职责拆分

生成工具可以提供形体起点，但最终生产链仍包含：

1. 轮廓确认；
2. 多视图一致性校正；
3. 可动画拓扑；
4. UV 与材质合并；
5. 骨骼和权重；
6. 攻击关键姿势；
7. Godot 碰撞与命中点；
8. iPhone 实机性能；
9. 来源和许可登记。

任何一步不合格，都不能因为“图看起来挺牛逼”跳过。

## M3 正式低模预算（首版建议）

| 资产 | 三角面目标 | 材质槽 | 骨骼 |
|---|---:|---:|---:|
| 无铭者 | 18k–30k | 2–3 | 55–75 |
| 造像署执刃者 | 10k–20k | 1–2 | 45–65 |
| 校刀令·迟盖 | 25k–40k | 2–3 | 60–85 |
| 长刀 | 1k–4k | 1 | 0–2 |
| 小场景模块 | 0.5k–8k | 1 | 0 |

预算是上限起点，不是必须把额度用光。轮廓、动作和批次优先于小配件。

## 导入约定

- 格式优先 `.glb`；
- 1 Godot 单位 = 1 米；
- 角色朝向 `-Z`；
- 原点在脚底中心；
- 动画名使用英文 snake_case；
- 不提交源软件缓存、个人签名或无用大贴图；
- 每个外部或生成资产登记来源、作者、工具、日期、许可和修改记录；
- 参考文物图不能未经核对直接做贴图投射。

## 验收问题

正式资产只有同时回答“是”才可替换灰盒：

1. 缩到手机实际显示尺寸后仍能辨认朝向吗？
2. 前摇关键姿势不靠红圈也看得懂吗？
3. 武器视觉长度和命中范围相符吗？
4. 换模型后是否保持战斗时间点？
5. 目标设备是否满足帧率和内存预算？
6. 授权链条能公开说明吗？
7. 历史锚点和架空改动写清楚了吗？
8. 是否混入了明显后世或异文化模板？
