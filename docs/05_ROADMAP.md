# 里程碑与验收标准

路线按“必须先证明什么”排序，不按日期许愿。世界观和美术可以并行探索，但不能绕过战斗验收。

## M0.2：Godot / 浏览器战斗研究样机（历史完成）

旧样机验证了：

- 镇军长刀三段攻击；
- 听刃与流影两种流派；
- 格挡、弹反、闪身、主动拼刀、架势与处决；
- 一个造像署执刃者；
- 浏览器触屏与桌面输入；
- 北齐历史母体、世界观与美术圣经。

Godot 版本保留在 Git 历史中；浏览器版保留为行为参考。二者不再作为正式主工程继续扩展。

## M0.3：Unity 迁移与基线恢复（当前）

### 已完成

- Unity 6.3 LTS 项目骨架；
- URP 与 Input System 依赖；
- C# `Combatant`、玩家、敌人、相机、HUD 和输入边界；
- 运行时灰盒场地；
- 移动、斩击、守、起手弹反、闪身、架势、崩势、处决；
- 普通明斩与延迟不可格挡重斩；
- 编辑器一键生成 `CombatSandbox.unity`；
- iOS 横屏、Bundle ID 与 IL2CPP 默认设置；
- 仓库静态校验。

### 尚未完成

- 在真实 Unity `6000.3.23f1` 中完成 Package restore 与编译；
- Play Mode 手感和连续重置测试；
- 长刀三段连段与输入缓存；
- 主动拼刀等级；
- 听刃 / 流影、锋意和四个武技；
- 移动端虚拟摇杆与按钮；
- iPhone 真机输入、震动、温度和帧率测试。

### 通过标准

- Unity Console 无编译错误；
- 连续重置十次不重复生成相机、HUD、角色或灯光；
- 玩家能区分普通命中、格挡、弹反、闪避、崩势与红招；
- 三次失败内能说明为什么挨打；
- Unity 版本至少恢复旧样机最有价值的决策；
- 一名非开发者试玩后愿意立刻再打。

## M1：一刀的手感

### 内容

- 三段连段和输入缓存；
- 主动拼刀；
- 命中停顿与统一反馈参数；
- 镜头轻震；
- 命中、格挡、弹反、拼刀、崩势五类音效；
- 刀光、火花、陶釉裂纹和红招提示；
- 触屏按钮布局 A/B；
- iPhone 真机性能记录。

### 通过标准

- 关闭文字日志仍能判断交互结果；
- 触屏弹反成功率不会因输入延迟明显低于键盘；
- 普通命中、压刀和弹反在声音、形状、停顿上互不混淆；
- 目标设备满足帧率预算；
- 测试者把失败归因到可说明的判断，而不是“游戏吞键”。

## M2：武器 × 流派 × 短局构筑

### 内容

- `ActionDefinition` 数据化；
- 战斗事件总线与 Modifier 系统；
- 听刃与流影完整移植；
- 8 个悟招与三选一界面；
- 三种普通敌人；
- 校刀令·迟盖小头目灰盒；
- 8–12 分钟房间流程；
- 错籍选择影响小头目第二阶段。

### 通过标准

- 悟招强化基本功，不替代正确读招；
- 听刃和流影不存在完全上位替代；
- 至少形成两条玩家能用一句话描述的联动；
- 一局有开场、推进、选择、小头目和结束；
- 历史线索通过空间与道具出现，不靠百科朗读。

## 每个里程碑的停止条件

出现以下情况立即停止堆内容：

- 战斗结果无法通过反馈辨认；
- 触屏误操作成为主要失败原因；
- 同一系统出现三套互相冲突的实现；
- 新内容只能复制整份脚本添加；
- 目标设备持续低于性能预算；
- 历史设计只能用“反正架空”解释；
- 测试者只说“数值不够”，而不是“我没处理好这一招”。
