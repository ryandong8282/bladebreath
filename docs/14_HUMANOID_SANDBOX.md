# 人形角色接入：第一次打开

这一版共用一个有真实男性面部、头发、手脚和完整骨骼的 MakeHuman 模型，生成无铭者和执刃者，并从 Quaternius UAL1/UAL2 与 KayKit 的十三条实际源动作建立十四个运行时槽位。西式合身服装已被压成不可见的旧布内衬；角色外层改为 Blender 生成的北朝军服轮廓，包括长衣、分片裙摆、前后札甲、双层肩甲、护臂、束发、空白铭牌和敌方灰陶面。它仍是一个训练场垂直切片和广义历史幻想设计，不冒充六世纪考古复原或完成的 iOS 游戏。

## 还没安装 Unity 时

Unity Hub 是管理项目和编辑器的启动器；只装 Hub 还不能运行游戏。先从 [Unity 官网](https://unity.com/download) 安装 Hub，再安装本仓库固定的 [Unity 6000.3.23f1](https://unity.com/releases/editor/whats-new/6000.3.23f1)。不要直接使用 Hub 首页推荐的其他版本打开工程。

首次使用需要你自己在 Hub 登录 Unity 账号，并按自己的资格激活相应许可证；符合条件时选择 Personal，不需要为这个小样购买素材。密码、验证码不用交给别人。

Windows 首次试玩只需编辑器本体，不必一起安装 Android、Web 或教程包。可以把编辑器放在空间充足的 D 盘。**不要点“新建项目”**：下面会打开已经准备好的工程。

## 你需要点哪里

1. 在 Unity Hub 安装仓库指定的 **Unity 6000.3.23f1**。Windows 先验证编辑器即可；最终 iOS 构建仍需 Mac、iOS Build Support 和 Xcode。
2. 点 **添加 → 从磁盘添加项目 / Add project from disk**，选择这个仓库的根目录（有 `Assets`、`Packages`、`ProjectSettings` 三个文件夹的那层）。Hub 3.21 首页的“导入项目”是扫描父目录里的多个工程，不是这个单个项目入口。
3. 等包还原、脚本编译结束。如果 Unity 提示启用新 Input System 后重启，接受它。
4. 点顶栏 **BladeBreath → Art → Create Humanoid Sandbox**。第一次会解压素材、创建 Humanoid Avatar、提取动作、生成材质、Animator 和角色外观 Prefab，并运行配置检查。没有下载、购买或登录资产商店的步骤。
5. 等到 Console 出现 **Human models are ready**，点上方 **▶ Play**，再点一下 Game 画面，让键盘操作进入游戏。

若菜单没有出现，先看 **Window → General → Console** 的第一条红色报错，不要反复下载资源。若人物仍是胶囊，确认当前打开的是 `HumanoidSandbox`，不是 `CombatSandbox`。

| 操作 | 按键 |
|---|---|
| 移动 | WASD / 方向键 |
| 三段轻击、靠近失衡敌人处决 | J / 鼠标左键 |
| 上段重斩 | L |
| 持续格挡、起手精准弹反 | K / 鼠标右键 |
| 闪身 | Space / Shift |
| 重新开打 | R |

手柄操作保持原样。手机虚拟摇杆和按钮尚未接入，这一步不要拿 iPhone 触屏操作当作已经完成。

再次执行菜单会保留已经生成的动画、材质、Prefab 和场景，不覆盖手工调整。原有 **Prototype → Create Combat Sandbox** 仍可生成胶囊灰盒作为对照。只有主动执行 **Art → Reimport Bundled Motions** 才会从两套已登记来源重新生成十四个槽位；该操作保留已有动画 GUID，并同步重建 Animator 状态，不改场景和角色外观。

## 灰窑外院画面升级

执行 **BladeBreath → Art → Apply Grey Kiln Art Pass** 会覆盖两套角色 Prefab 的视觉层，但保留同一路径、动画控制器和玩法根节点。角色共用 MakeHuman 真人身体，外接同一套 21 部件、18,968 三角面的轻量衣甲；侧裙、合身袖筒、肩甲、护臂、头饰和陶面分别跟随大腿、上臂、前臂和头骨。它不是布料模拟或全蒙皮定制服装，但已经用贴身长衣、袖筒和弧面甲片替代圆球、盒子与西服主轮廓。

Play Mode 会生成当前唯一竞技场：约 30 × 19 米的横向长方形石院，南侧进场石道、中央双环战圈、西侧残像工场、东侧烧造工场和北侧门楼形成五段连续空间。Blender 生成的门楼、巨像、砖窑、陶坯与军令碑使用十四个合并网格落入现有运行时材质层；脚手架、旗幡、碎石和两座带余烬的校刀窑继续由轻量 Unity 几何补足。镜头正对院落轴线，不把房间投影成菱形；院墙外还有扩展灰土地、道路、断墙、碎石、远窑和工棚剪影，不直接露出黑色虚空。石面与木架使用 Poly Haven 的 CC0 1K 颜色/法线贴图，Unity 导入上限固定为 1024、保留 mipmap 且关闭 CPU 可读，未加入位移、4K 或 8K 贴图。冷色方向光、两盏无阴影窑火、线性雾和低数量灰尘粒子构成氛围；每次 R 重开会销毁并重建这一套对象，运行检查要求始终只有一个庭院、一套 Blender 地标、一个 HUD、三盏设计灯和两名战斗者。

HUD 仍用 IMGUI，已经改为窄边框信息板、居中地点牌与底部按键条。刀光使用刀根与刀尖历史构成的运行时扇面，受击、格挡和崩势共用每名角色的一套小粒子系统。`CombatAudio` 播放挥刀、金属接触、身体命中、崩势、死亡、闪身衣料和距离步声。画面与声音都只观察 `Combatant`，不改变伤害、无敌、架势或攻击时钟。

原先十个顶点的盒状训练刀已由 Blender 生成的“镇军环首长刀”替换。新模型总长约 1.03 米、3,136 三角面，刀身、刃口、铜装和缠柄合并为四个材质组；它保留同一右手挂点、刀根/刀尖拖尾锚点、攻击距离和结算时钟，不添加第二把武器或新的碰撞所有者。刀身直、短格、缠柄和环首参考约公元 600 年中国实物的大轮廓；单刃军刀化、空白军籍片和简化环内纹样是本项目为了手机轮廓与“抹名”设定所作的架空处理。

Quaternius 两套源动画 FBX 都超过 10 MB，所以仓库各保留一个约 4.8 MB 的单文件无损压缩包；解压后的源文件位于对应 `Editor/Extracted` 目录并被 Git 忽略。UAL2 只把三段剑连击、冲斩和招架复制到运行时。KayKit 官方 Knight GLB 保存在 `SourceArt/`，约 2.6 MB 的 Editor-only FBX 只为格挡受力和左右闪身保留来源，不带角色网格与材质。游戏控制器只引用十四个独立 `.anim`。

## 动作与战斗如何连接

| 游戏动作 | 官方动画 | 当前处理 |
|---|---|---|
| 待机 | Idle_Loop | 循环 |
| 奔跑 | Jog_Fwd_Loop | 由实际位移驱动，与待机混合；快跑加速播放 |
| 三段轻击 | UAL2 Sword Regular A / B / C | 三段连击来自同一套带手指的 CC0 剑术组合；源动作的水平 Root Motion 已剥离，推进与碰撞根都由控制器统一负责，避免角色和敌人互相穿入 |
| 独立重击 / 背袭处决 | UAL2 Sword Dash | 正面 `L` 触发独立冲斩，忽略素材 Root Motion，由控制器负责位移；敌后近距 `L` 自动贴近并执行两断处决，处决全程无敌 |
| 格挡受力 | KayKit Block Hit | 独立格挡冲击动作并采样 0.16 秒，只表现受力，不改变格挡判定 |
| 举刀 / 持架 | UAL2 Sword Block | 弹反窗先明确举刀截线，随后把招架末帧保持为持架；不再用普通持刀 Idle 冒充招架 |
| 受击、失衡 | Hit_Chest | 短受击；失衡时保持反应姿势 |
| 闪身 | Roll / KayKit Dodge Left / Right | 无方向输入保留前滚；横向输入使用独立左右闪身，角色保持面向威胁，碰撞根和无敌时间仍由控制器决定 |
| 死亡 | Death01 | 不循环，结束后保持倒地 |

`Combatant`、`PlayerController`、`EnemyController` 继续负责所有战斗结果。`FighterPresentation` 只观察状态和动作进度，不能扣血或移动碰撞体。

角色结构为：

```text
Player / Enemy                     移动、碰撞、生命和攻击判定
└── ModelRoot                      FighterPresentation，可整体替换
    └── Humanoid                   Animator + Avatar + 骨骼网格
        └── … / hand.R / WeaponSocket / Longblade
```

骨骼映射、单位和轴转换由编辑器工具设置；Root Motion 关闭。三段攻击、短闪身、格挡受力和失衡状态暂停自动计时，由战斗进度采样；其余状态正常播放。Animator 的 `Speed` 和 `LocomotionRate` 控制移动表现。这样不需要同时维护“动画触发扣血”和“代码扣血”两套时间。

主角三段轻击前摇为 0.11、0.13、0.21 秒，后摇为 0.18、0.19、0.30 秒；生命/架势伤害分别为 `12/14`、`14/17`、`21/27`。独立重斩前摇 0.36 秒、后摇 0.44 秒，生命/架势伤害为 `30/44`。攻击只在各自动作的有效阶段开放命中；两个可格挡攻击有效阶段相遇时结算一次拼刀，双方不掉生命、增加架势并短暂后震。闪身 0.23 秒、无敌约 0.189 秒；敌人普通预警 0.48 秒、不可格挡重击预警 0.82 秒。受失衡/死亡会终止攻击协程，避免恢复站稳后又结算旧攻击。

四条 UAL2 攻击分别使用 `0.50 / 0.50 / 0.20 / 0.42` 的归一化接触采样，让可见刀路的最快段与现有战斗时钟对齐。表现层不再给完整身体动作叠加 80–150 度的刀柄旋转。刀轨在接触前开始记录刀根和刀尖，穿过命中帧后保留短暂随挥；命中范围依然由原来的球形判定负责，动态扇面与接触火花只负责表现，不能直接修改伤害或无敌。

死亡缩放和失衡倾斜现在只用于灰盒的模型子节点，不再改变玩法根节点的大小、朝向和碰撞。敌人预警结束后恢复各部位材质，不把陶甲、旧布、铜铁全部染成同一种颜色。重置会释放灰盒临时材质。

## 第一次验收

先运行 **BladeBreath → Art → Validate Humanoid Setup**。它检查 MakeHuman Avatar、真人网格数量、十四个动作槽位、四条攻击和左右闪身是否引用不同素材、运行时 1K 贴图上限、两套 Prefab、右手挂刀、材质、无额外碰撞体、重定向手部运动，以及格挡/弹反/不可格挡/闪避/崩势/处决/重置的战斗结果。

再运行 **Art → Run Humanoid Play Mode Checks**。它通过仅编辑器可用的确定性输入入口驱动真正的玩家控制器，检查镜头缩放、位移、三段轻击、刀轨采样、命中接触点、独立重斩、拼刀、格挡/弹反/闪避、处决及十次 R 重置。为隔离玩家输入，部分测试会暂停敌人 AI；这不等同于完整交锋的人工验收。报告写入忽略提交的 `Logs/humanoid-playmode-validation.txt`，结束后退出 Play Mode 并清除测试输入。

执行 **Art → Render Action Module Proof** 会清理旧证明图，定格输出斜斩、横斩、刺击、重劈、弹反、拼刀和左右闪身八张 PNG 到 `Logs/action-module-proof-frames/`，完成后自动回到原场景。它用于发现骨骼、刀向和轮廓问题，不替代实际连续动作试玩。

然后人工确认：

- Console 没有红色错误；模型直立、脚在地面、面朝移动方向。
- J 挥刀时刀与右手相连；命中时机没有明显早于刀经过敌人。
- K 能挡普通攻击；起手 K 能弹反；红色重击不能格挡。
- Space 有翻滚，不能因动画延长无敌；死后保持倒地，碰撞根节点不变扁。
- 失衡后不能结算被打断的攻击；靠近失衡敌人可处决。
- 连按/重复 R 十次后，场景中仍各只有一个玩家、一个敌人、一个 HUD 和一台主相机。
- Game 视图分别用 16:9、19.5:9 看清读招；敌人红/橙预警结束后恢复材质。

## 历史与风格边界

- **历史锚点**：沿用项目 `docs/04A_HISTORICAL_BIBLE.md` 中北齐石窟造像、石灰岩残彩和北方军武的方向。本次未增加新的考古复原结论。
- **架空处理**：空白铭牌和执刃者灰陶面已经落到服装模型；它们属于造像署删除军籍的虚构机制，不宣称是北齐实物。
- **玩法目的**：先区别玩家与敌人，识别朝向、持刀手和读招；不增加装备属性或第二把武器。
