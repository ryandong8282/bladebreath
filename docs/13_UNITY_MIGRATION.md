# Unity 迁移记录

## 决策

自 M0.3 起，正式主工程从：

```text
Godot 4.7.2 Standard + GDScript
```

切换为：

```text
Unity 6000.3.23f1 + C# + URP 17.3.0 + Input System 1.16.0
```

原因不是 Godot “不能做”，而是本项目目标包含 iOS 商业发布、3D 动作、较多动画与反馈调试、潜在外部资源采购和未来找人接手。对首次做游戏的单人开发者，Unity 在这些环节的资料、工具与人才池更适合当前风险结构。

## 保留了什么

- 全部产品、战斗、世界观、历史和美术文档；
- `prototype-web/`，作为旧战斗规则的可运行参考；
- Git 历史中的完整 Godot M0.2；
- 一把武器、两种流派、架势、锋意、拼刀和处决的设计语言；
- “先证明一刀，再做内容量”的范围护栏。

## 当前树移除了什么

- `project.godot`；
- Godot `.gd`、`.tscn`、`.tres` 运行时；
- Godot 下载与烟雾测试 CI；
- Godot 专用导出和校验脚本；
- 旧的 lowercase `assets/` 占位目录。

这些内容没有从 Git 历史消失。迁移前主分支提交为：

```text
e7b6d976c37f82c05fc754dc8d0972b32a3e469d
```

需要考古时查看该提交，不要把 Godot 文件重新复制回 Unity 主工程。

## 迁移原则

1. 不按旧文件逐行翻译；按玩家可见行为重建。
2. 每恢复一个系统，先写清它解决的战斗问题。
3. 旧样机与 Unity 结果冲突时，文档和试玩结论优先，不迷信旧实现细节。
4. Unity Package 数量保持克制。
5. 在核心手感稳定前，不购买大套美术资产来掩盖战斗问题。
6. 触屏层只产生意图，不拥有战斗规则。
7. Python 静态校验不能冒充 Unity 编译或真机测试。
